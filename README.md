# ClinicalCrew

**A production-grade multi-agent clinical decision support system built with CrewAI.**

Upload a medical report. Get a complete clinical package — structured diagnosis, evidence-based treatment options, drug interaction audit, patient-specific dosing, physician SOAP report, plain-language patient summary, and a structured follow-up plan — generated by 11 specialized AI agents across 4 sequential reasoning phases.

> **This is a clinical decision support tool, not a diagnostic or prescribing system.**
> Every output requires review and approval by a licensed physician before any clinical action is taken.

## What it does

ClinicalCrew takes a raw medical report — PDF, DOCX, or pasted text — and runs it through four sequential AI crews. Each crew has three specialized agents. By the time the pipeline completes, you have:

- A ranked differential diagnosis with likelihood scores and supporting evidence
- Interpretation of every lab value against reference ranges, with pattern recognition
- A risk stratification with validated clinical scores (CHADS2, Wells, qSOFA, TIMI)
- Evidence-graded treatment options (WHO / AHA / ADA / NICE / ESC) for each diagnosis
- A drug-drug and drug-disease interaction audit against the patient's current medications
- Patient-specific dosing adjusted for renal function (eGFR), hepatic function, age, and weight
- A physician SOAP report ready for the clinical record
- A plain-language patient summary written at a Grade 8 reading level
- A structured follow-up plan with appointments, repeat investigations, and emergency warning signs

## The 4-Phase Pipeline

### Phase 1 — Report Intake

| Agent | Responsibility |
|---|---|
| ReportParserAgent | Extracts demographics, vitals, labs with H/L/N/C flags, medications, allergies, imaging |
| PatientContextAgent | Builds comorbidity profile, drug class mapping, allergy cross-reactivity, clinical complexity score |
| DataValidatorAgent | Scores completeness (0–100), flags missing critical data, sets `safe_to_proceed` |

### Phase 2 — Diagnosis Analysis

| Agent | Responsibility |
|---|---|
| SymptomAnalyzerAgent | Symptom clustering, differential diagnosis ranked by likelihood with supporting/against evidence |
| LabInterpreterAgent | Reference range comparison, critical value flagging, pattern recognition (AKI, dyslipidemia, etc.) |
| RiskAssessorAgent | Overall risk level (low/moderate/high/critical), validated clinical scores, urgent vs. important actions |

### Phase 3 — Treatment Planning

| Agent | Responsibility |
|---|---|
| TreatmentSuggesterAgent | First-line, second-line, and alternative treatments with evidence grade and guideline source |
| DrugInteractionAgent | Drug-drug interactions (Major/Moderate/Minor), drug-disease contraindications, allergy alerts |
| DosageCalculatorAgent | Patient-specific dosing with renal/hepatic adjustments, daily schedule, titration notes |

### Phase 4 — Clinical Summary

| Agent | Responsibility |
|---|---|
| ReportWriterAgent | Structured SOAP physician report with items requiring clinical decision |
| PatientExplainerAgent | Plain-language patient summary — findings, medications, warning signs |
| FollowUpPlannerAgent | Appointments with timeframes, repeat investigations, specialist referrals, lifestyle recommendations |

## Per-Phase Model Selection

Each phase uses the model you select at runtime. There is no default — you choose before running. This means you can route different agents to different providers based on what you need.

Recommended configuration for best results with zero cost:

```
Phase 1 — Report Intake      →  Groq LLaMA 3.3 70B       (fast extraction)
Phase 2 — Diagnosis Analysis →  Gemini 2.5 Flash          (best reasoning)
Phase 3 — Treatment Planning →  Groq Qwen3 32B            (strong medical knowledge)
Phase 4 — Clinical Summary   →  OpenRouter GPT-OSS 120B   (long-form writing)
```

If you hit a rate limit, switch the phase to **OpenRouter Auto** (`openrouter/free`) — it routes automatically to the best available free model.

## Local Setup

**Requirements:** Python 3.11, Git

```bash
git clone https://github.com/YOUR_USERNAME/clinicalcrew.git
cd clinicalcrew
pip install -r requirements.txt
```

Add your API keys to `.streamlit/secrets.toml`:

```toml
GROQ_API_KEY       = "gsk_..."
GEMINI_API_KEY     = "AIza..."
OPENROUTER_API_KEY = "sk-or-..."
SUPABASE_URL       = "https://...supabase.co"

```

Run:

```bash
streamlit run app.py
```

Open `http://localhost:8501`.

## Deployment — Streamlit Community Cloud

1. Fork this repo and push to your GitHub account
2. Go to [share.streamlit.io](https://share.streamlit.io) and sign in with GitHub
3. Create app → select repo → set main file to `app.py`
4. Advanced settings → Python version → **3.11**
5. Advanced settings → Secrets → paste your keys in TOML format
6. Deploy

First deployment takes 3–5 minutes. Subsequent deploys are faster.

## Key Implementation Details

**Lazy loading** — Every agent is wrapped in a getter function. No agent is instantiated at module level. This prevents the `OPENAI_API_KEY is required` crash that occurs when Streamlit Cloud loads `st.secrets` before module-level code runs.

```python
# Wrong — crashes on Streamlit Cloud
llm = get_llm()
parser_agent = Agent(role="...", llm=llm)

# Correct
def get_report_parser_agent(phase_key: str = "phase1") -> Agent:
    return Agent(role="...", llm=_llm(phase_key), ...)
```

**Task parameter pattern** — Tasks receive their agent as a parameter rather than importing module-level instances.

```python
def task_parse_report(agent, report_text: str) -> Task:
    return Task(description=f"...", agent=agent)
```

**Safe JSON parsing** — Every agent output goes through `_safe_json()` before use. Agent outputs are not always valid JSON — this handles markdown fences, truncated output, and type mismatches.

```python
def _safe_json(raw) -> dict:
    try:
        text = str(raw).strip()
        if "```json" in text:
            text = text.split("```json")[1].split("```")[0].strip()
        elif "```" in text:
            text = text.split("```")[1].split("```")[0].strip()
        return json.loads(text)
    except Exception:
        return {"raw_output": str(raw)}
```

**Type-safe rendering** — Treatment and diagnosis output is rendered through `_safe_str()`, `_safe_dict()`, and `_safe_list()` helpers. Different models return the same logical data in different shapes. These helpers normalize it before the UI touches it.

**HTML rendering** — All complex HTML is rendered via `streamlit.components.v1.html()`. Using `st.markdown(unsafe_allow_html=True)` inside `st.columns()` loops causes layout corruption with custom CSS on Streamlit Cloud.

## Rate Limits — What to Do

**Groq TPM exceeded** — Switch the phase to a Gemini model or OpenRouter. Groq's free tier resets every minute — waiting 60 seconds usually resolves it.

**Gemini quota exceeded** — Switch to Groq or OpenRouter Auto. Gemini free tier resets daily.

**OpenRouter 429 on a `:free` model** — The specific model is rate-limited upstream. Switch to a different OpenRouter model or use `openrouter/free` which auto-selects.

**General strategy** — Run Phase 1 and 2 with Groq (fast, high TPM). Run Phase 3 and 4 with Gemini (better long-form output). Keep OpenRouter Auto as fallback for any phase that hits limits.

## Project Structure Rationale

This project was built with Streamlit Community Cloud constraints in mind from the start:

- No module-level agent instantiation (secrets not ready at import time)
- No `chromadb` or `pydantic` version pinning (CrewAI manages its own compatible versions)
- No `langchain-groq` (CrewAI's built-in `LLM` class handles all providers)
- No `crewai-tools` in requirements (bundled inside `crewai` 1.x)
- `crewai[google-genai]` extra required for Gemini provider support
- Python 3.11 required (3.12 breaks several CrewAI dependencies on Cloud)
